# 4.1 Ficheros o archivos

*Anterior: [3.5 Estructuras anidadas](../etapa-3-estructuras/3.5-estructuras-anidadas.md) — Siguiente: [4.2 Jerarquía de datos](4.2-jerarquia-de-datos.md)*

Todos los programas que has escrito hasta ahora tienen el mismo problema: **cuando terminan,
olvidan todo**. Registras a cinco alumnos, cierras el programa, lo vuelves a abrir y el arreglo
está vacío otra vez. Esta etapa resuelve eso: guardar los datos en un **archivo** (también
llamado **fichero**) para que sigan ahí la próxima vez.

## Dónde viven los datos de un programa

Mientras un programa corre, sus variables, arreglos y structs viven en la **memoria RAM**. La
RAM es rápida, pero es **volátil**: lo que tiene se pierde cuando el programa termina o cuando
se apaga la computadora.

Un archivo vive en un **almacenamiento permanente** (el disco duro, una SSD o una USB). Ahí los
datos se quedan aunque el programa termine y aunque se apague la computadora, hasta que alguien
los borre.

| | Memoria RAM | Archivo en disco |
|---|---|---|
| Qué guarda | Variables, arreglos y structs del programa | Datos guardados a propósito |
| Cuánto dura | Mientras el programa corre | Hasta que se borra |
| Velocidad | Muy rápida | Más lenta |
| Ejemplo | `Alumno grupo[30];` | `alumnos.txt` |

## Qué es un archivo

Un **archivo** es una colección de datos relacionados que se guarda con un nombre en un
almacenamiento permanente. Ya usas archivos todo el tiempo:

- Tu código de Dev-C++ se guarda en un archivo `.cpp`.
- Al compilar, Dev-C++ crea otro archivo, el `.exe`, que es el programa listo para correr.
- Una foto es un archivo `.jpg`; una canción, un `.mp3`; un trabajo escolar, un `.docx`.

Lo nuevo de esta etapa es que **tu propio programa** va a crear archivos, escribir en ellos y
leerlos después.

## El ciclo de vida de los datos, con y sin archivos

Sin archivos, los datos nacen y mueren con cada ejecución:

```
Ejecución 1:  capturas 5 alumnos  ->  los ves en la tabla  ->  sales  ->  se pierden
Ejecución 2:  el arreglo empieza vacío otra vez
```

Con archivos, una ejecución puede dejarle los datos a la siguiente:

```
Ejecución 1:  capturas 5 alumnos  ->  los guardas en alumnos.txt  ->  sales
Ejecución 2:  lees alumnos.txt  ->  los 5 alumnos vuelven al arreglo  ->  agregas un sexto
```

Ese es el objetivo de la etapa. Para llegar ahí verás qué contiene un archivo
([4.2](4.2-jerarquia-de-datos.md)), para qué sirve ([4.3](4.3-utilidad-de-los-ficheros.md)),
qué tipos hay ([4.4](4.4-tipos-de-ficheros.md)) y, a partir de
[4.5](4.5-programacion-con-ficheros.md), cómo se programan.

## Autocheck

**Registras 3 productos en un programa de la Etapa III y luego cierras el programa. ¿Dónde
estaban esos productos y por qué ya no están al volver a abrirlo?**

Estaban en un arreglo de structs, en la memoria RAM. La RAM es volátil: lo que guarda el
programa se pierde cuando el programa termina.

**¿Qué diferencia hay entre `productos[0]`, dentro de tu programa, y una línea del archivo
`productos.txt`?**

`productos[0]` vive en la RAM y desaparece al terminar el programa. La línea de `productos.txt`
vive en el disco y sigue ahí aunque el programa termine o se apague la computadora.

**Menciona dos archivos que crea Dev-C++ cuando escribes y compilas un programa.**

El `.cpp`, con el código que escribes, y el `.exe`, el programa compilado que se puede correr.
