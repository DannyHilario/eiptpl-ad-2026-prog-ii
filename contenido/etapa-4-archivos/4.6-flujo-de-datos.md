# 4.6 Flujo de datos (stream)

*Anterior: [4.5 Programación con ficheros](4.5-programacion-con-ficheros.md) — Siguiente: [4.7 Memoria intermedia](4.7-memoria-intermedia.md)*

En C++, la entrada y la salida se piensan como un **flujo** (en inglés, *stream*): una fila de
caracteres que pasa en orden, uno detrás de otro, como el agua de un río. `cin` es un flujo que
viene del teclado, `cout` es un flujo que va a la pantalla, y un archivo es un flujo más. Por
eso los tipos de archivo se llaman `ifstream` y `ofstream`: *input file stream* y *output file
stream*.

## Los datos llegan en orden

En un flujo no se puede brincar ni regresar: los caracteres se procesan en el orden en que
llegan. Si escribes `543`, primero llega el `5`, después el `4` y después el `3`.

Cada lectura con `>>` toma lo que sigue en el flujo y avanza. Es como un marcador que se mueve
hacia adelante: lo que ya se leyó no se vuelve a leer, y si el programa necesita empezar otra
vez desde el principio de un archivo, tiene que cerrarlo y abrirlo de nuevo.

## `>>` se salta los espacios y los saltos de renglón

Cuando `>>` lee un número o una palabra, primero se salta todos los espacios, tabuladores y
saltos de renglón, y después toma los caracteres hasta el siguiente espacio. Eso pasa igual con
`cin` que con un archivo. Puedes comprobarlo con el teclado:

```cpp
#include <iostream>
using namespace std;

int main() {
    int a, b, c;

    cout << "Escribe tres numeros: ";
    cin >> a;
    cout << "Ya lei a = " << a << endl;
    cin >> b >> c;
    cout << "Ya lei b = " << b << " y c = " << c << endl;

    return 0;
}
```

Si escribes los tres números en el mismo renglón y das Enter una sola vez:

```
Escribe tres numeros: 5 7 9
Ya lei a = 5
Ya lei b = 7 y c = 9
```

El programa no te vuelve a pedir nada: el `7` y el `9` ya estaban en el flujo, esperando su
turno. Y si escribes cada número en un renglón distinto, el resultado es el mismo, porque los
saltos de renglón también se saltan.

## Lo mismo en un archivo

Un archivo con estos datos, con espacios de más y renglones vacíos,

```
  10    20

30
```

se lee exactamente igual que uno con `10 20 30` en un solo renglón: `>>` entrega 10, después 20
y después 30. Lo que importa es el **orden** de los datos, no cómo estén acomodados.

Por eso, cuando un archivo guarda registros, el orden de los campos tiene que ser siempre el
mismo. Si cada renglón es `nombre calificacion`, el programa que lo lee tiene que leer primero
el nombre y después la calificación; si los lee al revés, intentará guardar `Sofia` en un
`double` y la lectura fallará.

## Autocheck

**Un programa hace `cin >> x;` y el usuario escribe `4 8 15` antes de dar Enter. ¿Qué vale `x`
y qué pasa con el 8 y el 15?**

`x` vale 4. El 8 y el 15 se quedan en el flujo y los recibirán las siguientes lecturas con `>>`.

**Un archivo tiene un número por renglón, pero con renglones vacíos entre ellos. ¿Afecta eso a
la lectura con `>>`?**

No: `>>` se salta los espacios y los saltos de renglón, incluidos los renglones vacíos.

**Ya leíste todo un archivo y quieres recorrerlo otra vez desde el principio. ¿Qué tienes que
hacer?**

Cerrarlo y volver a abrirlo; en un flujo secuencial no se puede regresar.

**Cada renglón de un archivo tiene `clave existencias`, por ejemplo `C01 25`. ¿En qué orden
debe leer el programa los dos campos?**

Primero la clave (un `string`) y después las existencias (un `int`), en el mismo orden en que
están escritos.
