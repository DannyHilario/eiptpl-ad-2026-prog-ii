# 4.7 Memoria intermedia (buffers)

*Anterior: [4.6 Flujo de datos](4.6-flujo-de-datos.md) — Siguiente: [4.8 Ficheros en C++](4.8-ficheros-en-cpp.md)*

Escribir en el disco es muchísimo más lento que escribir en la memoria RAM. Si el programa
fuera al disco por cada número o cada letra, sería lentísimo. Para evitarlo, C++ usa una
**memoria intermedia** (en inglés, *buffer*): una pequeña zona de la RAM donde se van juntando
los datos antes de mandarlos al disco de un solo golpe.

## Cómo funciona

Cuando haces `salida << "Hola";`, el texto **no** llega al disco en ese momento: se queda en el
buffer. El buffer se pasa al disco cuando:

- se llena;
- se cierra el archivo con `close()`;
- el programa termina normalmente (C++ cierra los archivos que sigan abiertos).

Es como juntar la ropa sucia en un cesto y lavarla toda junta, en lugar de echar a andar la
lavadora por cada calcetín.

## Lo que hay en el buffer todavía no está en el archivo

Este programa escribe `Hola` y, **antes de cerrar**, abre el mismo archivo para leerlo. Después
lo cierra y lo lee otra vez.

```cpp
#include <iostream>
#include <fstream>
#include <string>
using namespace std;

int main() {
    string palabra;
    int contador;

    ofstream salida("prueba.txt");
    salida << "Hola";              // queda en el buffer, todavia no en el disco

    // Antes de cerrar: otro flujo lee el archivo
    ifstream antes("prueba.txt");
    contador = 0;
    while (antes >> palabra) {
        contador++;
    }
    antes.close();
    cout << "Palabras antes de cerrar: " << contador << endl;

    salida.close();                // al cerrar, el buffer se pasa al disco

    // Despues de cerrar: se vuelve a leer
    ifstream despues("prueba.txt");
    contador = 0;
    while (despues >> palabra) {
        contador++;
    }
    despues.close();
    cout << "Palabras despues de cerrar: " << contador << endl;

    return 0;
}
```

Salida:

```
Palabras antes de cerrar: 0
Palabras despues de cerrar: 1
```

Antes de cerrar, el archivo existe pero está **vacío** en el disco: el `Hola` sigue en el
buffer. Al cerrar, el buffer se pasa al disco y la segunda lectura ya lo encuentra.

## Por qué siempre hay que cerrar

- **Para no perder datos.** Si el programa se interrumpe (se cuelga, se cierra la ventana a la
  fuerza o se va la luz), lo que estaba en el buffer nunca llega al disco.
- **Para que otro programa, o tu mismo programa, pueda leer lo escrito**, como en el ejemplo.
- **Para liberar recursos.** Cada archivo abierto ocupa memoria, y el sistema operativo limita
  cuántos puede tener abiertos un programa al mismo tiempo.

La regla del curso: **todo archivo que se abre se cierra con `close()` en cuanto se termina de
usar**, sin esperar a que termine el programa.

## Autocheck

**Un programa hace `salida << 25;` y en ese momento se va la luz. ¿Es seguro que el 25 quedó
guardado en el archivo?**

No. Lo más probable es que estuviera todavía en el buffer, en la RAM, y se perdiera.

**¿En qué momentos se pasa el buffer al disco?**

Cuando se llena, cuando se cierra el archivo con `close()` y cuando el programa termina
normalmente.

**En el ejemplo, ¿por qué la primera lectura cuenta 0 palabras si `Hola` ya se había escrito?**

Porque `Hola` estaba en el buffer de `salida` y todavía no había llegado al disco; el archivo
estaba vacío hasta el `close()`.
