# 4.9 Modos de apertura

*Anterior: [4.8 Ficheros en C++](4.8-ficheros-en-cpp.md) — Siguiente: [4.10 Actualización de archivos secuenciales](4.10-actualizacion-de-archivos-secuenciales.md)*

Al abrir un archivo se puede indicar un **modo de apertura**: qué se va a hacer con él y qué
pasa con lo que ya tenía. Hasta ahora usaste los modos por defecto, que son los más comunes.

| Modo | Qué hace | Por defecto en |
|---|---|---|
| `ios::out` | Abre para escribir. Si el archivo existe, **borra su contenido**; si no existe, lo crea | `ofstream` |
| `ios::app` | Abre para escribir **al final** (*append*, agregar). Conserva lo que ya tenía; si no existe, lo crea | — |
| `ios::in` | Abre para leer. Si el archivo no existe, la apertura **falla** | `ifstream` |

El modo se escribe después del nombre del archivo:

```cpp
ofstream a("datos.txt");              // igual que ofstream a("datos.txt", ios::out);
ofstream b("datos.txt", ios::app);    // agrega al final
ifstream c("datos.txt");              // igual que ifstream c("datos.txt", ios::in);
```

## `ios::out`: cada ejecución empieza de cero

```cpp
#include <iostream>
#include <fstream>
using namespace std;

int main() {
    int ejecucion;
    cout << "Numero de ejecucion: ";
    cin >> ejecucion;

    ofstream archivo("notas.txt");          // modo por defecto: sobrescribe
    archivo << "Escrito en la ejecucion " << ejecucion << endl;
    archivo.close();
    return 0;
}
```

Si lo corres dos veces (escribiendo 1 y después 2), `notas.txt` termina así:

```
Escrito en la ejecucion 2
```

La primera línea ya no está: al abrir en la segunda ejecución, el archivo se vació.

## `ios::app`: una bitácora que crece

Para un registro histórico, como una bitácora de temperaturas, lo que se necesita es **agregar**
sin borrar. Este programa captura la temperatura del día, la agrega al final de
`bitacora.txt` y luego lee la bitácora completa:

```cpp
#include <iostream>
#include <fstream>
using namespace std;

int main() {
    const double TEMP_MIN = -10;
    const double TEMP_MAX = 50;
    int dia;
    double temperatura;

    // 1) Capturar la lectura de hoy
    cout << "Dia del mes: ";
    cin >> dia;
    do {
        cout << "Temperatura (C): ";
        cin >> temperatura;
        if (temperatura < TEMP_MIN || temperatura > TEMP_MAX) {
            cout << "ERROR! Debe estar entre " << TEMP_MIN << " y " << TEMP_MAX << endl;
        }
    } while (temperatura < TEMP_MIN || temperatura > TEMP_MAX);

    // 2) Agregarla al final de la bitacora, sin borrar lo anterior
    ofstream salida("bitacora.txt", ios::app);
    if (!salida) {
        cout << "No se pudo abrir la bitacora." << endl;
        return 1;
    }
    salida << dia << " " << temperatura << endl;
    salida.close();

    // 3) Leer la bitacora completa y mostrarla
    ifstream entrada("bitacora.txt");
    int lecturas = 0;
    double suma = 0;
    cout << "\nBITACORA" << endl;
    while (entrada >> dia >> temperatura) {
        cout << "Dia " << dia << ": " << temperatura << " C" << endl;
        suma += temperatura;
        lecturas++;
    }
    entrada.close();
    cout << "Lecturas: " << lecturas << "   Promedio: " << suma / lecturas << " C" << endl;
    return 0;
}
```

Primera ejecución (la bitácora todavía no existe, así que `ios::app` la crea):

```
Dia del mes: 27
Temperatura (C): 31.5

BITACORA
Dia 27: 31.5 C
Lecturas: 1   Promedio: 31.5 C
```

Segunda ejecución, con un dato fuera de rango:

```
Dia del mes: 28
Temperatura (C): 60
ERROR! Debe estar entre -10 y 50
Temperatura (C): 29

BITACORA
Dia 27: 31.5 C
Dia 28: 29 C
Lecturas: 2   Promedio: 30.25 C
```

Tercera ejecución:

```
Dia del mes: 29
Temperatura (C): 26.5

BITACORA
Dia 27: 31.5 C
Dia 28: 29 C
Dia 29: 26.5 C
Lecturas: 3   Promedio: 29 C
```

Y así queda `bitacora.txt`, con un registro por ejecución:

```
27 31.5
28 29
29 26.5
```

Fíjate en el orden del programa: primero **escribe y cierra**, después **abre para leer**. Si
leyera sin haber cerrado la salida, la lectura de hoy podría seguir en el buffer
([4.7](4.7-memoria-intermedia.md)) y no aparecer.

## Cuál modo elegir

- **`ios::app`** cuando cada ejecución **agrega** registros nuevos y nunca hay que cambiar los
  anteriores: bitácoras, historial de ventas, registro de entradas.
- **`ios::out`** (el normal de `ofstream`) cuando el archivo se **reescribe completo** con
  información actualizada, como al guardar un inventario después de modificarlo
  ([4.10](4.10-actualizacion-de-archivos-secuenciales.md)).
- **`ios::in`** (el normal de `ifstream`) para leer.

## Autocheck

**`ventas.txt` tiene 10 renglones. Un programa lo abre con `ofstream v("ventas.txt");` y escribe
un renglón. ¿Cuántos renglones tiene ahora?**

Uno: el modo por defecto de `ofstream` borró los 10 anteriores.

**¿Y si lo hubiera abierto con `ofstream v("ventas.txt", ios::app);`?**

Once: los 10 que ya tenía y el nuevo al final.

**¿Qué pasa la primera vez que corre la bitácora, cuando `bitacora.txt` todavía no existe?**

`ios::app` crea el archivo, así que la primera lectura se guarda sin problema.

**¿Por qué el programa de la bitácora cierra `salida` antes de abrir `entrada`?**

Para que la lectura de hoy pase del buffer al disco; si no, la lectura del archivo podría no
encontrarla.
