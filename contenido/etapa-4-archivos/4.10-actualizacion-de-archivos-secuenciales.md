# 4.10 Actualización de archivos secuenciales

*Anterior: [4.9 Modos de apertura](4.9-modos-de-apertura.md)*

Agregar al final de un archivo es fácil con `ios::app`. Pero ¿y si hay que **cambiar** un dato
que ya está en medio del archivo, como las existencias de un producto? En un archivo de texto
secuencial no se puede "editar en su lugar". Esta sesión explica por qué y cómo se resuelve,
juntando todo lo de la etapa con los arreglos de structs de la Etapa III.

## Por qué no se puede cambiar un dato en su lugar

Un archivo de texto es una sola fila de caracteres ([4.2](4.2-jerarquia-de-datos.md)). Supón
que `inventario.txt` tiene:

```
C01 Lapiz 25
C02 Cuaderno 12
```

y que hay que cambiar el nombre `Lapiz` por `Portaminas`. `Portaminas` tiene cinco letras más
que `Lapiz`; si se escribiera encima, en el mismo lugar, las letras de más **pisarían** lo que
sigue:

```
C01 Portaminas02 Cuaderno 12
```

El espacio, las 25 existencias y el salto de renglón del primer registro desaparecieron, y del
segundo registro se perdió la `C` de su clave: los dos quedaron revueltos en un solo renglón.
Lo mismo pasa al cambiar 25 existencias por 100: un número con más cifras ocupa más
caracteres. Por eso, en un archivo secuencial de texto, **los registros no se modifican en su
lugar**.

## La solución: cargar, modificar y reescribir

En lugar de tocar el archivo, se trabaja en memoria:

1. **Cargar:** se lee el archivo completo a un **arreglo de structs**, con un contador de
   registros, igual que en la Etapa III.
2. **Modificar:** los cambios se hacen en el arreglo (agregar, cambiar un campo), con todo lo
   que ya sabes hacer.
3. **Reescribir:** se abre el archivo con `ofstream` en su modo normal (que lo vacía) y se
   escribe otra vez **completo**, un renglón por registro.

Como el archivo se vuelve a escribir desde cero, no importa que un dato haya crecido o se haya
hecho más corto.

## Un inventario que recuerda

```cpp
#include <iostream>
#include <fstream>
#include <string>
using namespace std;

const int MAX_PRODUCTOS = 10;
const string ARCHIVO = "inventario.txt";

struct Producto {
    string clave;
    string nombre;
    int existencias;
};

int main() {
    Producto productos[MAX_PRODUCTOS];
    int n = 0;                  // cuantos productos hay en el arreglo
    int opcion;

    // 1) CARGAR: del archivo al arreglo (si el archivo no existe, se empieza vacio)
    ifstream entrada(ARCHIVO.c_str());
    while (n < MAX_PRODUCTOS &&
           entrada >> productos[n].clave >> productos[n].nombre >> productos[n].existencias) {
        n++;
    }
    entrada.close();
    cout << "Productos cargados: " << n << endl;

    // 2) MODIFICAR: todo se hace en el arreglo, en memoria
    do {
        cout << "\n1. Ver  2. Agregar  3. Cambiar existencias  4. Guardar y salir" << endl;
        do {
            cout << "Opcion: ";
            cin >> opcion;
            if (opcion < 1 || opcion > 4) {
                cout << "ERROR! La opcion debe estar entre 1 y 4" << endl;
            }
        } while (opcion < 1 || opcion > 4);

        if (opcion == 1) {
            for (int i = 0; i < n; i++) {
                cout << productos[i].clave << "  " << productos[i].nombre
                     << "  " << productos[i].existencias << endl;
            }
        } else if (opcion == 2) {
            if (n == MAX_PRODUCTOS) {
                cout << "El inventario esta lleno." << endl;
            } else {
                cout << "Clave: ";
                cin >> productos[n].clave;
                cout << "Nombre (una palabra): ";
                cin >> productos[n].nombre;
                do {
                    cout << "Existencias: ";
                    cin >> productos[n].existencias;
                    if (productos[n].existencias < 0) {
                        cout << "ERROR! No puede ser negativo" << endl;
                    }
                } while (productos[n].existencias < 0);
                n++;
            }
        } else if (opcion == 3) {
            string clave;
            int posicion = -1;
            cout << "Clave a cambiar: ";
            cin >> clave;
            for (int i = 0; i < n; i++) {
                if (productos[i].clave == clave) {
                    posicion = i;
                }
            }
            if (posicion == -1) {
                cout << "No existe esa clave." << endl;
            } else {
                do {
                    cout << "Existencias nuevas de " << productos[posicion].nombre << ": ";
                    cin >> productos[posicion].existencias;
                    if (productos[posicion].existencias < 0) {
                        cout << "ERROR! No puede ser negativo" << endl;
                    }
                } while (productos[posicion].existencias < 0);
            }
        }
    } while (opcion != 4);

    // 3) GUARDAR: se reescribe el archivo completo con lo que hay en el arreglo
    ofstream salida(ARCHIVO.c_str());
    if (!salida) {
        cout << "No se pudo guardar el inventario." << endl;
        return 1;
    }
    for (int i = 0; i < n; i++) {
        salida << productos[i].clave << " " << productos[i].nombre
               << " " << productos[i].existencias << endl;
    }
    salida.close();
    cout << "Inventario guardado: " << n << " productos." << endl;
    return 0;
}
```

### Primera ejecución: el archivo no existe

Como `inventario.txt` todavía no existe, la apertura de `entrada` falla, el `while` no lee nada
y el programa empieza con `n = 0`. Se agregan tres productos (uno de ellos con un dato
inválido) y se guarda:

```

1. Ver  2. Agregar  3. Cambiar existencias  4. Guardar y salir
Opcion: 2
Clave: C01
Nombre (una palabra): Lapiz
Existencias: 25

1. Ver  2. Agregar  3. Cambiar existencias  4. Guardar y salir
Opcion: 2
Clave: C02
Nombre (una palabra): Cuaderno
Existencias: -3
ERROR! No puede ser negativo
Existencias: 12

1. Ver  2. Agregar  3. Cambiar existencias  4. Guardar y salir
Opcion: 2
Clave: C03
Nombre (una palabra): Borrador
Existencias: 40

1. Ver  2. Agregar  3. Cambiar existencias  4. Guardar y salir
Opcion: 4
Inventario guardado: 3 productos.
```

`inventario.txt` queda así:

```
C01 Lapiz 25
C02 Cuaderno 12
C03 Borrador 40
```

### Segunda ejecución: el inventario se recuerda

Al volver a abrir el programa, los tres productos se cargan del archivo. Se cambian las
existencias del cuaderno y se guarda:

```
Productos cargados: 3

1. Ver  2. Agregar  3. Cambiar existencias  4. Guardar y salir
Opcion: 3
Clave a cambiar: C02
Existencias nuevas de Cuaderno: 30

1. Ver  2. Agregar  3. Cambiar existencias  4. Guardar y salir
Opcion: 1
C01  Lapiz  25
C02  Cuaderno  30
C03  Borrador  40

1. Ver  2. Agregar  3. Cambiar existencias  4. Guardar y salir
Opcion: 4
Inventario guardado: 3 productos.
```

Y el archivo, reescrito completo, ya tiene el cambio:

```
C01 Lapiz 25
C02 Cuaderno 30
C03 Borrador 40
```

## Lo que hay que notar

- **La carga respeta la capacidad del arreglo.** La condición `n < MAX_PRODUCTOS` va **antes**
  de la lectura: si el archivo trajera más de 10 productos, el programa deja de leer en lugar de
  escribir fuera del arreglo.
- **La lectura va directo a los campos del registro** (`entrada >> productos[n].clave >> ...`).
  Si la lectura falla, `n` no aumenta, así que solo cuentan los registros completos.
- **El archivo y el arreglo usan el mismo formato y el mismo orden de campos**: clave, nombre y
  existencias, separados por espacios y un registro por renglón.
- **El archivo solo se toca dos veces:** al empezar, para cargar, y al terminar, para guardar.
  Todo lo demás pasa en el arreglo. Si se cierra el programa sin elegir la opción 4, los cambios
  de esa ejecución no se guardan.
- **Al guardar se usa `ofstream` en su modo normal** (no `ios::app`): el archivo tiene que
  quedar con el contenido actual del arreglo, no con el viejo más el nuevo.

## Autocheck

**¿Por qué no se puede cambiar `Lapiz` por `Portaminas` escribiendo directamente sobre el
archivo?**

Porque `Portaminas` ocupa más caracteres y pisaría lo que sigue en el archivo: las existencias,
el salto de renglón y el principio del siguiente registro.

**¿Cuáles son los tres pasos para actualizar un archivo secuencial?**

Cargar el archivo completo a un arreglo de structs, modificar el arreglo en memoria y reescribir
el archivo completo con el arreglo.

**Al guardar el inventario, ¿qué pasaría si se abriera la salida con `ios::app`?**

Los registros se agregarían al final de los que ya estaban: el archivo tendría el inventario
anterior y después el nuevo, con todos los productos repetidos.

**`inventario.txt` tiene 12 renglones y `MAX_PRODUCTOS` vale 10. ¿Cuántos productos se cargan y
por qué el orden de la condición `n < MAX_PRODUCTOS && entrada >> ...` es importante?**

Se cargan 10. Como `n < MAX_PRODUCTOS` se revisa primero, cuando `n` llega a 10 la condición ya
es falsa y no se intenta leer en `productos[10]`, una posición que no existe.

**En la primera ejecución, `inventario.txt` no existe. ¿Por qué el programa no marca error?**

Porque al fallar la apertura el `while` no lee ningún registro y el programa simplemente
empieza con `n = 0`. Para un inventario nuevo eso es lo que se quiere.
