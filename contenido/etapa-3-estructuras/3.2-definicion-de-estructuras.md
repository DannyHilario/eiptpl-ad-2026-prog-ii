# 3.2 Definición de estructuras

*Anterior: [3.1 Estructuras](3.1-estructuras.md) — Siguiente: [3.3 Inicialización de estructuras](3.3-inicializacion-de-estructuras.md)*

En la sesión anterior usaste un `struct` sin detenerte en las reglas. Ahora sí: cómo se
escribe, dónde va, qué crea exactamente y qué errores son los más comunes.

## La sintaxis

```cpp
struct Producto {
    string nombre;
    int existencias;
    double precio;
};
```

| Parte | Qué es |
|---|---|
| `struct` | Palabra reservada que inicia la definición |
| `Producto` | El nombre del tipo nuevo. Por convención empieza con mayúscula (PascalCase), para distinguirlo de las variables |
| `{ ... }` | La lista de miembros: cada uno con su tipo y su nombre, como cualquier declaración de variable |
| `;` después de `}` | **Obligatorio.** Olvidarlo es el error más común con structs |

Los miembros pueden ser de cualquier tipo que ya conoces: `int`, `double`, `char`, `bool`,
`string` e incluso arreglos (por ejemplo, `double calificaciones[3];` dentro del struct).

## Definir un tipo no es declarar una variable

Esta es la idea más importante de la sesión. La definición de `Producto` **no reserva
memoria ni guarda ningún dato**: solo le describe al compilador cómo es un producto. Es como
el plano de una casa: describe los cuartos, pero no es una casa.

Los datos existen cuando **declaras variables** de ese tipo:

```cpp
Producto lapiz;      // una variable de tipo Producto
Producto cuaderno;   // otra, con sus propios tres campos
```

`lapiz` y `cuaderno` son independientes: cada uno tiene su `nombre`, sus `existencias` y su
`precio`. Cambiar `lapiz.precio` no afecta a `cuaderno.precio`.

## Dónde se escribe

La definición del `struct` va **antes de `main`** (y antes de cualquier función que lo use),
justo después de los `#include` y del `using namespace std;`. Así, todo el programa conoce el
tipo.

Ojo: eso **no** convierte a las variables en globales. Lo que va afuera es el **tipo**; las
variables se siguen declarando dentro de `main`, igual que siempre.

```cpp
#include <iostream>
#include <string>
using namespace std;

struct Producto {          // el TIPO: afuera de main
    string nombre;
    int existencias;
    double precio;
};

int main() {
    Producto lapiz;        // las VARIABLES: dentro de main
    Producto cuaderno;

    lapiz.nombre = "Lapiz";
    lapiz.existencias = 120;
    lapiz.precio = 6.5;

    cuaderno.nombre = "Cuaderno";
    cuaderno.existencias = 35;
    cuaderno.precio = 42;

    cout << lapiz.nombre << ": " << lapiz.existencias << " piezas a $" << lapiz.precio << endl;
    cout << cuaderno.nombre << ": " << cuaderno.existencias << " piezas a $" << cuaderno.precio << endl;

    return 0;
}
```

Salida:

```
Lapiz: 120 piezas a $6.5
Cuaderno: 35 piezas a $42
```

## Copiar un struct completo

Dos variables del mismo tipo de struct se pueden copiar con un solo `=`: se copian **todos**
los campos a la vez.

```cpp
Producto respaldo;
respaldo = lapiz;          // copia nombre, existencias y precio
respaldo.precio = 7;       // cambia solo la copia; lapiz.precio sigue en 6.5
```

Lo que **no** se puede es comparar dos structs completos con `==` ni imprimir uno completo
con `cout`: el compilador no sabe qué significa "igual" ni cómo mostrar un `Producto`. Se
compara y se imprime **campo por campo**:

```cpp
if (lapiz.precio == respaldo.precio) {   // bien: compara un campo
    cout << "Mismo precio" << endl;
}
// if (lapiz == respaldo)   -> no compila
// cout << lapiz;           -> no compila
```

## Errores comunes

| Error | Ejemplo | Qué pasa |
|---|---|---|
| Olvidar el `;` final | `struct Producto { ... }` | Error de compilación, a veces señalado en la línea **siguiente**, lo que lo hace difícil de encontrar |
| Usar el tipo como si fuera variable | `Producto.precio = 6.5;` | No compila: `Producto` es el plano, no una variable. Debe ser `lapiz.precio` |
| Olvidar el punto o escribir mal el campo | `lapiz precio`, `lapiz.Precio` | No compila. Los nombres de los campos distinguen mayúsculas y minúsculas |
| Definir el struct después de `main` | `struct` escrito al final del archivo | No compila: cuando `main` declara `Producto lapiz;`, el tipo todavía no existe |

## Autocheck

**¿Cuánta memoria reserva esta definición, sin nada más en el programa: `struct Fecha { int
dia; int mes; int anio; };`?**

Ninguna. Solo define el tipo `Fecha`. La memoria se reserva cuando declaras una variable,
por ejemplo `Fecha hoy;`.

**¿Por qué no compila `Producto.precio = 6.5;`?**

Porque `Producto` es el nombre del tipo, no una variable. Hay que declarar una variable
(`Producto lapiz;`) y usar su nombre: `lapiz.precio = 6.5;`.

**Si haces `respaldo = lapiz;` y luego `lapiz.existencias = 0;`, ¿cuánto vale
`respaldo.existencias`?**

120. El `=` hizo una copia de todos los campos en ese momento; después las dos variables son
independientes, así que cambiar `lapiz` no cambia `respaldo`.

**¿Cómo sabes si dos productos tienen el mismo nombre?**

Comparando el campo, no el struct completo: `if (lapiz.nombre == cuaderno.nombre)`.
`lapiz == cuaderno` no compila.
