# 3.3 Inicialización de estructuras

*Anterior: [3.2 Definición de estructuras](3.2-definicion-de-estructuras.md) — Siguiente: [3.4 Arreglos de registros](3.4-arreglos-de-registros.md)*

En la sesión anterior llenaste los campos uno por uno, con una asignación por línea. Funciona,
pero cuando ya conoces los datos desde el principio hay una forma más corta: **inicializar**
el struct en el mismo momento en que lo declaras, igual que haces con `int total = 0;`.

## Un struct sin inicializar tiene basura

Igual que una variable `int` o `double` sin valor inicial, los campos numéricos de un struct
recién declarado contienen **lo que haya quedado en esa memoria**:

```cpp
Producto goma;
cout << goma.existencias;   // puede salir cualquier número
```

Los campos `string` son la excepción: siempre empiezan como texto vacío (`""`). Pero los
`int` y `double` no, así que nunca uses un campo antes de darle valor. No cuentes con que el
compilador te avise: muchas veces compila sin ninguna advertencia.

## Inicializar con llaves

Escribe los valores entre llaves, **en el mismo orden en que se declararon los campos**:

```cpp
struct Producto {
    string nombre;
    int existencias;
    double precio;
};

Producto lapiz = {"Lapiz", 120, 6.5};
```

El primer valor va a `nombre`, el segundo a `existencias` y el tercero a `precio`. El orden
importa: si los escribes en otro orden, o el compilador se queja o, peor, los datos quedan en
el campo equivocado.

```cpp
Producto malo = {120, "Lapiz", 6.5};   // no compila: 120 no puede ir en un string
Producto peor = {"Lapiz", 6, 120};     // compila, pero existencias = 6 y precio = 120
```

El segundo caso es el peligroso: compila sin errores y el programa da resultados
equivocados. Por eso conviene tener a la vista la definición del struct cuando escribes la
lista.

## Inicialización parcial y en ceros

Si escribes **menos** valores que campos, los que faltan quedan en cero (o vacíos, si son
`string`):

```cpp
Producto nuevo = {"Regla"};   // existencias = 0, precio = 0
Producto vacio = {};          // nombre = "", existencias = 0, precio = 0
```

`= {}` es la forma más corta de garantizar que un struct empiece **limpio**, sin basura. Es el
equivalente a `int total = 0;` para structs.

## Capturar desde el teclado

Cuando los datos los da el usuario, no hay valores que poner entre llaves: se capturan campo
por campo con `cin`, como en [3.1](3.1-estructuras.md). La validación funciona igual que con
cualquier variable, porque cada campo **es** una variable de su tipo.

## Ejemplo completo: valor del inventario

```cpp
#include <iostream>
#include <string>
using namespace std;

struct Producto {
    string nombre;
    int existencias;
    double precio;
};

double calcularValor(int existencias, double precio);

int main() {
    Producto lapiz = {"Lapiz", 120, 6.5};   // datos conocidos: llaves
    Producto capturado = {};                // datos del usuario: empieza limpio

    cout << "Nombre del producto: ";
    cin >> capturado.nombre;

    do {
        cout << "Existencias (0 o mas): ";
        cin >> capturado.existencias;
        if (capturado.existencias < 0) {
            cout << "ERROR! No puede ser negativo." << endl;
        }
    } while (capturado.existencias < 0);

    do {
        cout << "Precio (mayor a 0): ";
        cin >> capturado.precio;
        if (capturado.precio <= 0) {
            cout << "ERROR! Debe ser mayor a 0." << endl;
        }
    } while (capturado.precio <= 0);

    double valorLapiz = calcularValor(lapiz.existencias, lapiz.precio);
    double valorCapturado = calcularValor(capturado.existencias, capturado.precio);

    cout << endl;
    cout << lapiz.nombre << ": $" << valorLapiz << endl;
    cout << capturado.nombre << ": $" << valorCapturado << endl;
    cout << "Valor total del inventario: $" << valorLapiz + valorCapturado << endl;

    return 0;
}

double calcularValor(int existencias, double precio) {
    return existencias * precio;
}
```

Con la entrada `Cuaderno`, `-5`, `35`, `0`, `42`, imprime:

```
Nombre del producto: Existencias (0 o mas): ERROR! No puede ser negativo.
Existencias (0 o mas): Precio (mayor a 0): ERROR! Debe ser mayor a 0.
Precio (mayor a 0):
Lapiz: $780
Cuaderno: $1470
Valor total del inventario: $2250
```

Fíjate en la función `calcularValor`: es una función **pura**, como las de la Etapa I, y
recibe los **campos** que necesita (`existencias` y `precio`), no el struct completo. Cada
campo es un `int` o un `double` normal, así que se pasa como cualquier argumento. Pasar el
struct completo a una función también se puede; se verá más adelante.

## Autocheck

**¿Qué valores tiene cada campo después de `Producto p = {"Goma", 15};`?**

`nombre = "Goma"`, `existencias = 15` y `precio = 0`. El campo que no recibe valor en la
lista queda en cero.

**Querías registrar 25 gomas a $8 cada una y escribiste `Producto q = {"Goma", 8, 25};`.
Compila. ¿Qué quedó guardado?**

`existencias = 8` y `precio = 25`, porque los valores se asignan en el orden de los campos
(`nombre`, `existencias`, `precio`). El programa funciona, pero con los datos al revés: el
reporte diría que hay 8 gomas a $25 cada una.

**¿Para qué sirve `Producto capturado = {};` si de todos modos se van a capturar los datos?**

Para que el struct empiece limpio, sin basura en sus campos numéricos. Si el programa usara
un campo antes de capturarlo (por error o por un cambio futuro), tendría 0 y no un número
cualquiera.

**¿Por qué `calcularValor` recibe `existencias` y `precio` y no un `Producto`?**

Porque solo necesita esos dos datos, y así sigue siendo una función pura con parámetros
`int` y `double` como las de la Etapa I.
