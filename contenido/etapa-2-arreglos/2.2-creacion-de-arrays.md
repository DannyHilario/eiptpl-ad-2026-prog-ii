# 2.2 Creación de arrays

*Anterior: [2.1 Arreglos](2.1-arreglos.md) — Siguiente: [2.3 Inicialización de arrays](2.3-inicializacion-de-arrays.md)*

## Sintaxis de declaración

```cpp
<tipo> <nombre>[<numero de elementos>];
```

Por ejemplo:

```cpp
int edades[5];
```

Esto crea un arreglo de 5 enteros, accesibles como `edades[0]` hasta `edades[4]`. El
`<tipo>` puede ser cualquiera que ya conoces (`int`, `double`, `char`, ...), pero
**todos los elementos del arreglo deben ser del mismo tipo** — no se pueden mezclar
`int` y `double` en un mismo arreglo.

## El tamaño debe ser una constante

El número de elementos entre corchetes debe conocerse **en tiempo de compilación** —
no puede ser una variable que cambie mientras el programa corre. Por eso es buena
práctica usar una constante con nombre en vez de un número mágico repetido:

```cpp
#include <iostream>
using namespace std;

int main() {
    const int TAMANO = 5;
    int edades[TAMANO];

    for (int i = 0; i < TAMANO; i++) {
        edades[i] = 15 + i;
    }

    for (int i = 0; i < TAMANO; i++) {
        cout << "edades[" << i << "] = " << edades[i] << endl;
    }

    return 0;
}
```

Salida:

```
edades[0] = 15
edades[1] = 16
edades[2] = 17
edades[3] = 18
edades[4] = 19
```

Usar `TAMANO` en vez de escribir `5` en cada `for` significa que, si el tamaño
cambia, se corrige en una sola línea — la misma idea de evitar números mágicos que ya
aplicaste en los ejercicios de la etapa anterior.

## Arreglos de dos dimensiones (matrices)

Para una matriz se agrega un segundo par de corchetes, uno por cada dimensión:

```cpp
int tablero[3][2];  // 3 filas, 2 columnas
```

El número de dimensiones que se pueden usar solo está limitado por la memoria
disponible, pero en este curso trabajamos con una o dos.

## C++ no verifica los límites de un arreglo

Esta es la advertencia más importante de esta sesión: **C++ no revisa, mientras el
programa corre, si el índice que usas está dentro del arreglo.** Si declaras un
arreglo de 5 elementos y accedes al índice 7, el compilador no lo detecta (salvo
casos muy simples donde el índice es un número fijo y el compilador puede
anticiparlo) y el programa sigue corriendo — solo que ahora está leyendo o
escribiendo en una zona de memoria que **no le pertenece**, y el resultado es
impredecible: puede que "funcione" por casualidad, puede que corrompa el valor de
otra variable, o puede que el programa se cierre de golpe.

```cpp
#include <iostream>
using namespace std;

int main() {
    int vector[5] = {1, 2, 3, 4, 5};
    int centinela = 999;
    int indice;

    cout << "Indice a escribir: ";
    cin >> indice;

    // Si el usuario entra 7, esto escribe fuera del arreglo (indices
    // validos: 0 a 4). El compilador no lo puede anticipar porque
    // "indice" se conoce hasta que el programa corre.
    vector[indice] = 100;

    cout << "centinela = " << centinela << endl;

    return 0;
}
```

Si a este programa le das como índice `7`, el comportamiento **no está definido**:
en una corrida puede que `centinela` aparezca con un valor distinto a 999 (porque
`vector[7]` en realidad cayó encima de la memoria de `centinela`), en otra puede que
el programa se cierre abruptamente. No hay una salida "correcta" que memorizar aquí
— el punto es que **nunca debes confiar en que C++ te avise** si te pasaste del
límite; es responsabilidad tuya asegurarte de que el índice siempre esté entre `0` y
`tamaño - 1`.

## Autocheck

**¿Por qué el tamaño de un arreglo debe ser una constante y no una variable normal?**

Porque el tamaño se fija en tiempo de compilación — el compilador necesita saber
cuánta memoria reservar antes de que el programa corra, y eso no es posible si el
tamaño depende de un valor que solo se conoce durante la ejecución.

**Si declaras `double precios[8]` y accedes a `precios[10]`, ¿el compilador marca
error?**

En general no. C++ no verifica los límites del arreglo en tiempo de ejecución, así
que el programa compila y corre, pero accede a memoria que no le pertenece —
comportamiento indefinido, no un error controlado.

**¿Qué declaración crea una matriz de 4 filas y 3 columnas de enteros?**

`int matriz[4][3];`
