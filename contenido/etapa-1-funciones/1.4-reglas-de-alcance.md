# 1.4 Reglas de alcance

*Anterior: [1.3 Funciones definidas por el usuario](1.3-funciones-definidas-por-el-usuario.md)*

El **alcance** (*scope*) de un identificador (variable, función, parámetro) es la
parte del programa donde ese nombre existe y se puede usar. Ya usaste variables
dentro de `main()` sin pensarlo, pero al empezar a combinar varias funciones en un
mismo programa, entender el alcance deja de ser opcional: es lo que evita — o
explica — errores confusos de "esta variable ya no existe aquí" o "estoy usando la
variable que no era".

## Alcance de bloque (el más común)

Una variable declarada dentro de un bloque `{ }` (el cuerpo de una función, un `if`,
un `for`) solo existe **desde donde se declara hasta el `}` que cierra ese bloque**.
Los parámetros de una función también son variables locales de esa función, con el
mismo alcance de bloque.

```cpp
#include <iostream>
using namespace std;

void ejemplo() {
    int x = 10;   // x nace aqui
    if (x > 5) {
        int y = 20;  // y nace aqui, solo existe dentro de este if
        cout << x << " " << y << endl;
    }
    // aqui "y" ya no existe -- usarla marcaria error de compilacion
}

int main() {
    ejemplo();
    return 0;
}
```

## Alcance de archivo (variables globales)

Un identificador declarado **fuera de cualquier función** (arriba de todo, junto a
los `#include`) tiene alcance de archivo: se puede usar desde cualquier función del
archivo, a partir del punto donde se declaró. A estas variables se les llama
**globales**.

Las variables globales son cómodas porque cualquier función las puede leer y
modificar sin que se las pases como parámetro — pero esa misma comodidad es
peligrosa: si diez funciones distintas modifican la misma variable global, rastrear
quién la cambió y cuándo se vuelve difícil. **Usa variables globales con
moderación**; en la gran mayoría de los casos, pasar la información como parámetro
(lo que ya aprendiste en la sesión anterior) es más claro y más seguro.

## Variables locales vs. globales con el mismo nombre

Si una función declara una variable local con el mismo nombre que una variable
global, la local **oculta** a la global mientras se ejecuta esa función — es un caso
de alcance de bloque compitiendo con alcance de archivo, y siempre gana el bloque
más interno.

**Ejemplo 1**

```cpp
#include <iostream>
using namespace std;

int contador = 100;

void usarContadorLocal();

int main() {
    cout << "Contador global desde main: " << contador << endl;

    usarContadorLocal();

    cout << "Contador global despues de usarContadorLocal: " << contador << endl;

    return 0;
}

void usarContadorLocal() {
    int contador = 5;
    cout << "Contador local dentro de usarContadorLocal: " << contador << endl;
    contador++;
    cout << "Contador local despues de incrementar: " << contador << endl;
}
```

Salida:

```
Contador global desde main: 100
Contador local dentro de usarContadorLocal: 5
Contador local despues de incrementar: 6
Contador global despues de usarContadorLocal: 100
```

El `contador` local de `usarContadorLocal` es una variable completamente distinta al
`contador` global — vive solo mientras esa función se ejecuta, se incrementa a 6, y
al terminar la función desaparece sin haber tocado en absoluto al `contador` global,
que sigue en 100. Esto casi siempre es un **error lógico** cuando ocurre por
accidente (querías modificar la global, pero sin querer declaraste una local con el
mismo nombre) — por eso es importante entenderlo, no solo memorizarlo.

## Variables `static` locales: alcance de bloque, pero duran todo el programa

Una variable local normal se crea cada vez que se llama a la función, y se destruye
al salir de ella — por eso no "recuerda" nada entre una llamada y la siguiente. Si le
pones la palabra `static` al declararla, sigue teniendo alcance de bloque (solo se
puede usar dentro de esa función), pero su valor **se conserva entre llamadas**: se
inicializa una sola vez, la primera vez que se ejecuta esa línea, y de ahí en
adelante conserva su valor.

**Ejemplo 2**

```cpp
#include <iostream>
using namespace std;

void registrarLlamada();

int main() {
    registrarLlamada();
    registrarLlamada();
    registrarLlamada();

    return 0;
}

void registrarLlamada() {
    static int veces = 0;
    veces++;
    cout << "Esta funcion se ha llamado " << veces << " veces." << endl;
}
```

Salida:

```
Esta funcion se ha llamado 1 veces.
Esta funcion se ha llamado 2 veces.
Esta funcion se ha llamado 3 veces.
```

Si `veces` no fuera `static`, cada llamada a `registrarLlamada` reiniciaría `veces`
en 0, y el programa siempre imprimiría "1 veces" — probar quitar el `static` es un
buen ejercicio para confirmar esto por tu cuenta.

## Alcance de prototipo de función

Los nombres que usas dentro de un prototipo (`int mayor(int a, int b);`) solo
existen dentro de ese prototipo — el compilador ni siquiera los usa para nada más
que legibilidad, como vimos en la sesión anterior. Puedes reutilizar esos mismos
nombres (`a`, `b`) como variables en cualquier otra parte del programa sin que haya
conflicto.

## Autocheck

**Si una variable se declara dentro de un `for`, ¿hasta dónde existe?**

Hasta la llave `}` que cierra el bloque del `for`. Fuera de ese bloque, ya no existe
y usarla sería un error de compilación.

**En el Ejemplo 1, ¿por qué el `contador` global sigue valiendo 100 al final, si
`usarContadorLocal` lo incrementó?**

Porque `usarContadorLocal` declaró su **propia** variable local llamada `contador`,
que oculta a la global mientras la función se ejecuta. El incremento (`contador++`)
afectó a esa variable local, no a la global — son dos variables distintas que
comparten nombre por coincidencia.

**¿Qué pasaría en el Ejemplo 2 si quitas la palabra `static` de `veces`?**

El programa imprimiría "1 veces" las tres veces, porque sin `static`, `veces` se
crea y se inicializa en 0 cada vez que se llama a la función, y se destruye al
terminarla — no hay forma de que "recuerde" cuántas veces se llamó antes.

**¿Es buena práctica usar muchas variables globales para pasar información entre
funciones?**

No, en general. Es más difícil rastrear qué función modificó una variable global y
cuándo, especialmente en programas grandes. Pasar la información como parámetros
(y regresarla con `return`) hace explícito qué entra y qué sale de cada función.
