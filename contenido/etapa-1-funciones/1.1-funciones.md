# 1.1 Funciones

*Siguiente: [1.2 Funciones predefinidas](1.2-funciones-predefinidas.md)*

## ¿Qué es una función?

Una **función** es un bloque de código con nombre que resuelve una tarea específica.
Puede recibir datos de entrada (**parámetros**), hacer algo con ellos, y
opcionalmente regresar un resultado (**valor de retorno**) — ambas cosas son
opcionales e independientes entre sí: hay funciones sin parámetros, funciones que no
regresan nada, y todas las combinaciones posibles.

Ya usaste una función sin pensarlo: `main()` es una función — la única obligatoria
en todo programa de C++ (la vemos a fondo en
[1.3 Funciones definidas por el usuario](1.3-funciones-definidas-por-el-usuario.md)).
`cout` y `cin`, en cambio, **no son funciones** — son objetos (`cout` es de tipo
`ostream`, `cin` de tipo `istream`, ambos declarados en `<iostream>`). No los llamas
con paréntesis como a una función normal; los usas con los operadores `<<` y `>>`.
Por ahora basta con distinguir: `main()` sí es una función, `cout`/`cin` no lo son,
aunque las tres cosas viven dentro de la misma línea de código cuando escribes
`cout << resultado;` dentro de `main()`. Lo que cambia a partir de ahora es que tú
vas a **crear tus propias funciones**, además de usar las que ya vienen en C++.

## ¿Por qué dividir un programa en funciones?

Hasta ahora, un programa típico era un solo bloque de código dentro de `main()`.
Funciona mientras el programa es pequeño, pero se vuelve difícil de leer y de
corregir en cuanto crece: encontrar un error significa releer todo, y reutilizar una
parte de la lógica significa copiarla y pegarla.

La idea central es **dividir y vencer**: un problema grande se resuelve escribiendo
varias funciones pequeñas, cada una responsable de una sola tarea, y combinándolas.

Ventajas concretas:

- **Evitas repetir código.** Si necesitas calcular un promedio en tres partes del
  programa, escribes la función una vez y la llamas tres veces.
- **Aíslas errores.** Si el promedio sale mal, sabes exactamente en qué función
  buscar, en vez de revisar todo `main()`.
- **El código se lee como una lista de pasos.** Un `main()` bien dividido en
  funciones se lee casi como una receta: `leerDatos(); calcularPromedio();
  mostrarResultado();`.

## Ejemplo 1 — evitas repetir código

Este ejemplo reporta la categoría de 3 estudiantes según su calificación
(Excelente / Bien / Suficiente / No aprobado). A diferencia de una fórmula de una
sola línea, aquí lo que se repite es una cadena de decisiones de 4 casos — así se ve
mejor el ahorro real de código, no solo la protección contra errores de fórmula.

**Sin función** — la misma cadena de `if`/`else if` copiada 3 veces:

```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    string nombre;
    double calificacion;

    cout << "Nombre del estudiante 1: ";
    cin >> nombre;
    cout << "Calificacion de " << nombre << ": ";
    cin >> calificacion;
    if (calificacion >= 9) {
        cout << nombre << ": Excelente" << endl;
    } else if (calificacion >= 8) {
        cout << nombre << ": Bien" << endl;
    } else if (calificacion >= 6) {
        cout << nombre << ": Suficiente" << endl;
    } else {
        cout << nombre << ": No aprobado" << endl;
    }

    cout << "Nombre del estudiante 2: ";
    cin >> nombre;
    cout << "Calificacion de " << nombre << ": ";
    cin >> calificacion;
    if (calificacion >= 9) {
        cout << nombre << ": Excelente" << endl;
    } else if (calificacion >= 8) {
        cout << nombre << ": Bien" << endl;
    } else if (calificacion >= 6) {
        cout << nombre << ": Suficiente" << endl;
    } else {
        cout << nombre << ": No aprobado" << endl;
    }

    cout << "Nombre del estudiante 3: ";
    cin >> nombre;
    cout << "Calificacion de " << nombre << ": ";
    cin >> calificacion;
    if (calificacion >= 9) {
        cout << nombre << ": Excelente" << endl;
    } else if (calificacion >= 8) {
        cout << nombre << ": Bien" << endl;
    } else if (calificacion >= 6) {
        cout << nombre << ": Suficiente" << endl;
    } else {
        cout << nombre << ": No aprobado" << endl;
    }

    return 0;
}
```

**Con función** — la cadena de decisiones vive una sola vez:

```cpp
#include <iostream>
#include <string>
using namespace std;

string categorizarCalificacion(double calificacion);

int main() {
    string nombre;
    double calificacion;

    cout << "Nombre del estudiante 1: ";
    cin >> nombre;
    cout << "Calificacion de " << nombre << ": ";
    cin >> calificacion;
    cout << nombre << ": " << categorizarCalificacion(calificacion) << endl;

    cout << "Nombre del estudiante 2: ";
    cin >> nombre;
    cout << "Calificacion de " << nombre << ": ";
    cin >> calificacion;
    cout << nombre << ": " << categorizarCalificacion(calificacion) << endl;

    cout << "Nombre del estudiante 3: ";
    cin >> nombre;
    cout << "Calificacion de " << nombre << ": ";
    cin >> calificacion;
    cout << nombre << ": " << categorizarCalificacion(calificacion) << endl;

    return 0;
}

string categorizarCalificacion(double calificacion) {
    if (calificacion >= 9) {
        return "Excelente";
    } else if (calificacion >= 8) {
        return "Bien";
    } else if (calificacion >= 6) {
        return "Suficiente";
    }
    return "No aprobado";
}
```

Los dos programas hacen exactamente lo mismo y dan el mismo resultado, pero la
versión con función tiene **11 líneas menos** — no por eliminar `cin`/`cout` (esas
se siguen escribiendo 3 veces, porque hay 3 estudiantes distintos), sino porque la
parte que sí es idéntica cada vez — decidir la categoría — vive en un solo lugar. Si
mañana cambian los rangos de calificación (por ejemplo, "Excelente" desde 9.5), en
la versión con función se corrige en **una** línea; en la versión sin función habría
que encontrar y corregir las 3 copias, con el riesgo de dejar una desactualizada.

## Ejemplo 2 — aíslas errores (y reutilizas en contextos distintos)

Una función que hace descuentos sobre el precio de un boleto de cine, usada en tres
situaciones distintas de la misma taquilla (no son 3 copias del mismo caso, son 3
casos distintos que comparten la misma fórmula):

**Sin función** — la fórmula del descuento repetida 3 veces, con un error metido a
propósito (suma el descuento en vez de restarlo):

```cpp
#include <iostream>
using namespace std;

int main() {
    double precioBoleto = 80.0;

    double precioEstudiante = precioBoleto + (precioBoleto * 20 / 100);
    cout << "Precio con descuento de estudiante (20%): $" << precioEstudiante << endl;

    double precioTerceraEdad = precioBoleto + (precioBoleto * 30 / 100);
    cout << "Precio con descuento de tercera edad (30%): $" << precioTerceraEdad << endl;

    double precioPromoMartes = precioBoleto + (precioBoleto * 50 / 100);
    cout << "Precio con promocion de martes (50%): $" << precioPromoMartes << endl;

    return 0;
}
```

Con el error, esto imprime `$96`, `$104` y `$120` — un "descuento" que en realidad
sube el precio. Para corregirlo hay que encontrar y cambiar **las 3 líneas**, una
por una, con el riesgo de dejar alguna sin corregir.

**Con función** — la misma fórmula, pero escrita una sola vez:

```cpp
#include <iostream>
using namespace std;

double calcularPrecioConDescuento(double precio, double porcentajeDescuento);

int main() {
    double precioBoleto = 80.0;

    double precioEstudiante = calcularPrecioConDescuento(precioBoleto, 20);
    cout << "Precio con descuento de estudiante (20%): $" << precioEstudiante << endl;

    double precioTerceraEdad = calcularPrecioConDescuento(precioBoleto, 30);
    cout << "Precio con descuento de tercera edad (30%): $" << precioTerceraEdad << endl;

    double precioPromoMartes = calcularPrecioConDescuento(precioBoleto, 50);
    cout << "Precio con promocion de martes (50%): $" << precioPromoMartes << endl;

    return 0;
}

double calcularPrecioConDescuento(double precio, double porcentajeDescuento) {
    return precio + (precio * porcentajeDescuento / 100);
}
```

Con el mismo error (`+` en vez de `-`), esta versión imprime exactamente los mismos
valores incorrectos — pero para corregirla basta con cambiar **una sola línea**, la
del `return` dentro de `calcularPrecioConDescuento`:

```cpp
double calcularPrecioConDescuento(double precio, double porcentajeDescuento) {
    return precio - (precio * porcentajeDescuento / 100);
}
```

Con esa única corrección, los tres descuentos (estudiante, tercera edad, promoción
de martes) quedan arreglados a la vez — `$64`, `$56` y `$40`, verificado
compilando. Ese es el "aíslas errores" de la lista de ventajas: cuando sabes que el
descuento está mal, sabes exactamente en qué función buscar, y arreglarla arregla
los tres casos que la usan.

## Ejemplo 3 — el código se lee como una lista de pasos

Un programa que imprime un ticket de compra sencillo, con encabezado, cálculo del
total con IVA, y pie de ticket:

**Sin funciones** — todo junto en `main()`:

```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "===== Tienda EIPTPL =====" << endl;
    cout << "Ticket de compra" << endl;
    cout << "--------------------------" << endl;

    double subtotal;
    cout << "Subtotal de la compra: ";
    cin >> subtotal;

    const double IVA = 0.16;
    double total = subtotal + (subtotal * IVA);

    cout << "--------------------------" << endl;
    cout << "Total a pagar (IVA incluido): $" << total << endl;
    cout << "Gracias por tu compra." << endl;

    return 0;
}
```

**Con funciones** — cada parte del ticket es un paso con nombre:

```cpp
#include <iostream>
using namespace std;

void mostrarEncabezado();
double calcularTotalConIVA(double subtotal);
void mostrarTicket(double total);

int main() {
    mostrarEncabezado();

    double subtotal;
    cout << "Subtotal de la compra: ";
    cin >> subtotal;

    double total = calcularTotalConIVA(subtotal);
    mostrarTicket(total);

    return 0;
}

void mostrarEncabezado() {
    cout << "===== Tienda EIPTPL =====" << endl;
    cout << "Ticket de compra" << endl;
    cout << "--------------------------" << endl;
}

double calcularTotalConIVA(double subtotal) {
    const double IVA = 0.16;
    return subtotal + (subtotal * IVA);
}

void mostrarTicket(double total) {
    cout << "--------------------------" << endl;
    cout << "Total a pagar (IVA incluido): $" << total << endl;
    cout << "Gracias por tu compra." << endl;
}
```

Los dos dan exactamente el mismo resultado, verificado compilando ambos con
`$150` de subtotal. La diferencia está en qué tan rápido entiendes `main()` sin leer
el resto del archivo: en la segunda versión, con solo leer `mostrarEncabezado();`,
`cin >> subtotal;`, `calcularTotalConIVA(subtotal)` y `mostrarTicket(total);`, ya
sabes qué hace el programa de principio a fin — cada nombre de función documenta su
propio paso, sin necesidad de leer su cuerpo. Nota también que `mostrarEncabezado`
y `mostrarTicket` son `void`: existen solo para imprimir, no para calcular nada.

## ¿Debe una función hacer `cin`/`cout` ella misma, o solo calcular?

Nota que en el ejemplo anterior, `categorizarCalificacion` **no** hace `cin` ni
`cout` — solo recibe un número y regresa un texto. Quien lee el teclado y quien
imprime es `main()`. Esto no es casualidad: es una práctica extendida en ingeniería
de software separar el **cálculo** (la lógica pura: dado este dato, produce este
resultado) de la **entrada/salida** (leer teclado, archivos, pantalla, red).

- Las [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines)
  (la guía de buenas prácticas de C++ mantenida por Bjarne Stroustrup y Herb Sutter)
  recomiendan que una función que produce un resultado lo regrese con `return` en
  vez de mezclarlo con otras responsabilidades — la regla F.20 dice explícitamente
  que hay que preferir el valor de retorno sobre parámetros de salida o efectos
  secundarios.
- El principio de diseño **CQS (Command-Query Separation)**, propuesto por Bertrand
  Meyer, establece que una función debería *hacer algo* (como `cin`/`cout`, que
  cambian el estado del programa o del mundo exterior) o *responder algo* (calcular
  y regresar un valor) — pero no ambas a la vez, porque mezclar las dos
  responsabilidades hace la función más difícil de leer, probar y reutilizar.
- El patrón **"Functional Core, Imperative Shell"** (núcleo funcional, cáscara
  imperativa) formaliza esta misma idea: toda la entrada/salida se concentra en la
  capa "de afuera" del programa (aquí, `main()`), mientras el núcleo que calcula se
  mantiene libre de I/O — así se puede probar y reutilizar sin depender de teclado,
  pantalla o archivos.

**Razón práctica para este curso:** si `categorizarCalificacion` tuviera su propio
`cin` adentro, solo podría usarse leyendo del teclado. Cuando el curso llegue a la
Etapa IV (archivos), vas a querer categorizar calificaciones que vienen de un
archivo, no del teclado — y una función que solo calcula (sin `cin` propio) funciona
igual sin cambiar una sola línea, mientras que una función con `cin` integrado
tendrías que reescribirla.

**Regla práctica para el curso:** el `cin`/`cout` va en `main()` (o en la función que
esté orquestando el programa); las funciones que escribas para calcular o decidir
algo reciben lo que necesitan como parámetros y regresan su resultado con `return`,
sin leer ni imprimir nada por su cuenta.

## Dos tipos de funciones

A partir de aquí vamos a distinguir entre:

1. **Funciones predefinidas** — ya vienen listas para usar en bibliotecas de C++
   (como `sqrt` para raíz cuadrada). Las vemos en
   [1.2 Funciones predefinidas](1.2-funciones-predefinidas.md).
2. **Funciones definidas por el usuario** — las que tú escribes, como
   `categorizarCalificacion` en el ejemplo anterior. Las vemos a fondo en
   [1.3 Funciones definidas por el usuario](1.3-funciones-definidas-por-el-usuario.md).

## Autocheck

**¿Una función necesita obligatoriamente recibir parámetros y regresar un valor?**

No. Ambas cosas son opcionales e independientes: puede haber funciones sin
parámetros, funciones que no regresan nada (`void`), o cualquier combinación.

**En el ejemplo "sin función", ¿qué pasaría si necesitáramos agregar un cuarto
estudiante?**

Habría que copiar y pegar el bloque completo de `cin` + cadena de `if`/`else if`
una vez más, con el riesgo de equivocarse al copiarlo. En la versión con función,
solo hay que agregar las líneas de `cin` para ese estudiante y una llamada a
`categorizarCalificacion`, sin repetir la cadena de decisiones.

**¿Por qué `categorizarCalificacion` no hace `cin` ni `cout` ella misma?**

Porque separar el cálculo (decidir la categoría) de la entrada/salida (leer
teclado, imprimir pantalla) hace la función reutilizable en cualquier contexto —
por teclado, por archivo, con datos ya calculados — sin tener que reescribirla. Es
la práctica que respaldan las C++ Core Guidelines, CQS y el patrón "Functional
Core, Imperative Shell".

**En el Ejemplo 2, si el error (`+` en vez de `-`) estuviera en la versión "sin
función", ¿cuántas líneas habría que revisar para asegurarte de haberlo corregido
en todos lados? ¿Y en la versión con función?**

En la versión sin función, 3 líneas — una por cada descuento calculado
directamente en `main()` — y hay que revisar las 3 para confirmar que ninguna se
quedó con el error. En la versión con función, solo 1 línea: el `return` dentro de
`calcularPrecioConDescuento`, porque los tres descuentos pasan por esa misma
función.

**En el Ejemplo 3, ¿por qué `mostrarEncabezado` y `mostrarTicket` son `void` en vez
de regresar algo?**

Porque su trabajo es imprimir texto en pantalla, no calcular un valor que
`main()` vaya a usar después — son funciones que *hacen algo* (imprimir), no que
*responden algo* (calculan y regresan). Es la misma distinción de "Command-Query
Separation" que vimos más arriba para justificar por qué `cin`/`cout` van en
`main()` y no dentro de funciones de cálculo.
